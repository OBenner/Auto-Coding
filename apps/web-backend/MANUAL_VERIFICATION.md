# Manual Authentication Verification

This document describes the manual verification process for API authentication in the Auto Claude Web Backend.

## Prerequisites

Before running the manual verification, ensure:

1. **Backend dependencies are installed:**
   ```bash
   cd apps/web-backend
   pip install -r requirements.txt
   ```

2. **Backend server is running:**
   ```bash
   cd apps/web-backend
   python -m uvicorn main:app --host localhost --port 8000
   ```

   Or:
   ```bash
   cd apps/web-backend
   python main.py
   ```

## Automated Verification Scripts

Two verification scripts have been created for convenience:

### Linux/Mac:
```bash
cd apps/web-backend
chmod +x verify_authentication.sh
./verify_authentication.sh
```

### Windows:
```bash
cd apps/web-backend
verify_authentication.bat
```

## Manual Verification Steps

If you prefer to run the tests manually, follow these steps:

### Test 1: Request without authentication (should return 401)

```bash
curl -i http://localhost:8000/api/tasks
```

**Expected Response:**
- HTTP Status: `401 Unauthorized`
- Response body should contain an authentication error message

### Test 2: Request with invalid token (should return 401)

```bash
curl -i -H "Authorization: Bearer invalid" http://localhost:8000/api/tasks
```

**Expected Response:**
- HTTP Status: `401 Unauthorized`
- Response body should indicate invalid credentials

### Test 3: Get valid token from /api/auth/verify

```bash
curl http://localhost:8000/api/auth/verify
```

**Expected Response:**
- HTTP Status: `200 OK`
- Response body contains a JSON object with a `token` field
- Copy the token value for use in the next test

Example response:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 1440
}
```

### Test 4: Request with valid token (should return 200)

Replace `<YOUR_TOKEN>` with the token from Test 3:

```bash
curl -i -H "Authorization: Bearer <YOUR_TOKEN>" http://localhost:8000/api/tasks
```

**Expected Response:**
- HTTP Status: `200 OK`
- Response body contains a JSON array of tasks

## Additional Verification Tests

### Test 5: Verify /api/specs requires authentication

```bash
curl -i http://localhost:8000/api/specs
```

**Expected:** `401 Unauthorized`

### Test 6: Verify /api/agents/run requires authentication

```bash
curl -i -X POST http://localhost:8000/api/agents/run \
  -H "Content-Type: application/json" \
  -d '{}'
```

**Expected:** `401 Unauthorized`

### Test 7: Verify /health endpoint is public (no auth required)

```bash
curl -i http://localhost:8000/health
```

**Expected:** `200 OK` (even without authentication)

## Troubleshooting

### Server won't start

1. Check if dependencies are installed:
   ```bash
   pip install -r requirements.txt
   ```

2. Check if port 8000 is already in use:
   ```bash
   # Linux/Mac
   lsof -i :8000

   # Windows
   netstat -ano | findstr :8000
   ```

3. Check for environment variable issues in `.env` file

### All requests return 500 Internal Server Error

Check the server logs for detailed error messages. Common issues:
- Missing `.env` file or `SECRET_KEY` not set
- Database connection issues
- Missing required dependencies

### Token verification fails

Ensure the `SECRET_KEY` in the backend's `.env` file matches the one used to generate tokens.

## Notes

All API endpoints (except `/health`, `/`, and `/docs`) require JWT authentication via the `Authorization: Bearer <token>` header.

Tokens are generated by the `/api/auth/verify` endpoint and expire after 24 hours (configurable via `ACCESS_TOKEN_EXPIRE_MINUTES` in `.env`).
